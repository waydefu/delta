# ACFH 2.1｜原生 3D 材質棚拍、燈光與真實分件聚焦

## 本次交付

承接 ACFH 2.0 全幅舞台，這次優先提升可用的 **Three.js 原生 3D**；需使用者主動點選「真實 AKM 3D」才下載 GLB／初始化 WebGL，維持首屏 2D 快速載入。

### 對已核實的本地 GLB 進行實際渲染改善

- **PBR 材質原樣保留**：沿用 GLTFLoader 的材質與 RoomEnvironment 的 PMREM，不用 CSS 濾鏡假稱替換了金屬、木材的貼圖。Render 使用 ACESFilmic、SRGB 輸出。
- **燈光棚拍方案**：電影光影、材質比對、細節檢視是直接改 Three.js Hemisphere/Directional light 的照度與 toneMapping exposure，不是只換背景色。
- **投影陰影**：桌面端為真 GLB mesh 啟用 castShadow，另在模型下方建立接受陰影的實際圓形地台幾何。手機／粗指標停用陰影圖以控制 GPU 使用量。這個地台是布景，不是武器分件。
- **攝影機**：保留原 OrbitControls 的旋轉／縮放，新增真實 `AKM_Magazine` 網格 bounds 的視角聚焦與可取消、限時 540ms 攝影機過渡，重設回全槍。使用者拖動即中止自動過渡；使用者關閉 3D 也會釋放影格。
- **選配件紀錄與 3D 顯示分開**：研究模式選裝的槍托／槍口等會在原生 3D HUD 直接列出名稱，旁邊明確標註 **3D 模型未隨配件更換**。不做虛假的幾何替換。
- 不變更試算引擎、精調規則、目前 45 件研究配件的值、2D SVG/插畫及 GitHub 原有資料權限。

## 事實限制（必須維持）

本地 AKM GLB 的已驗證幾何仍僅有 **2 個 mesh、1 種材質**；真實彈匣 `AKM_Magazine` 可獨立隱藏、檢視／動畫及攝影機聚焦。其他槍口、槍托、握把等只是資料層槽位，**未包含可替換的正確 3D 幾何或掛點**。

光影的完成度確實會因單一材質及模型細節有限而受限；新增的場景地台**不可以視為已完成武器零件**。本次既沒有宣稱取得遊戲原版武器檔，也沒有新拉未經查核的第三方資產或變更作者授權。

## 行動版效能與可用性

- Three.js 只在手動進 3D 時才動態 import，與第一階段首屏分離。
- 桌面陰影採單一主光 PCFSoftShadowMap 1024²；手機及粗指標不建立實時投影陰影圖。
- 背景不啟用 perpetual requestAnimationFrame；OrbitControls change 才重繪，攝影機過渡僅在按鈕被點擊時執行。
- 手機控制列可捲動，包含獨立、有狀態的 3 個燈光模式、聚焦彈匣、重設視角、材質／網格、彈匣裝卸。
- 減少動效時聚焦立即切換；攝影機動畫在離開 viewer 時取消。
- `dispose()` 釋放場景地台、PMREM、mesh 貼圖與資產、renderer、controls、resize observer，並中止動畫；保留原本 2D 返回顯示。

## 驗收門檻

- Node：燈光 preset 定義合理值、只允許具名獨立網格聚焦、禁止不實 3D 換件、資料試算仍完全隔離。
- Chromium/SwiftShader：桌面及 390px 手機點進原生 3D，驗證電影／中性／細節三組真正改變 scene 的燈光；聚焦已核實彈匣，再回全槍；維持原彈匣裝卸動畫（位移回零）、WebGL 資源退出時可釋放。
- 2D/手機 360/390、reduced motion、no WebGL 完整回歸；不得自動載入 3D。
- 僅主 CI + 兩套 real-browser 成功才 squash merge。

## 後續「真正分件」P0

- 取得 CC0／CC BY、可審核來源和對應模型版本的高品質 AKM mesh，再驗證槍口、槍管、木質護木、握把、槍托和彈匣的**獨立節點及局部座標**。
- 建立掛點、互斥和獨立裝配約束，並讓資料選擇 state 對應到正確的部件 mesh；若資料不完整，一律保留靜態模型與明確提示。
- 針對 Android 中高階裝置建立幀率、GPU 使用與畫質等級的可測效能門檻，而不是單純加更多 Shader。
