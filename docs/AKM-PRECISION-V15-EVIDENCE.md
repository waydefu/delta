# AKM Precision v1.5｜詳細屬性與精調證據邊界（2026-10-25）

## 為什麼需要獨立資料層

使用者指出同一槍托的綜合面板除了後座、操控，還有據槍穩定、腰射；部分配件另有額外垂直／水平後座、開火時穩定性，並因精調而變化。這些不是單一指標。

**目前不得宣稱**：後座 +8 能直接轉換為精確垂直倍率或水平倍率。精調滑桿的幅度／範圍與版本也未逐件驗證。這版本不改變 `src/engine.mjs` 的主要研究試算算術，**不虛構精調後的性能或反推真實後座軌跡**。

## 已建構的資料分層

- `data/weapons/akm.json`：裸槍主要面板（使用者 2026-10-23 行動版截圖），原始基準保留。
- `data/attachments/akm-sample.json`：配件候選及 4 大面板研究修正；目前 45 件，未有逐件同版本實機核實。
- `data/weapons/akm-details.json`：已截圖核對的裸槍**方向性後座／開火時武器穩定／開火時鏡頭穩定／操控時間／腰射角度**等細項。
- `data/research/akm-precision-protocol.json`：將後座分成全自動垂直、全自動水平、單發／連發垂直、單發／連發水平，另把開火時武器穩定、開火時鏡頭穩定、呼吸、腰射角度等分開；只記錄各類配件「常見」精調維度，**不保證每件都可調**。
- `data/research/akm-precision-observations.json`：目前刻意保留空紀錄；尚無同版手機烽火 AKM 逐配件精調結果。
- `src/precision.mjs`：逐版本、逐模式、逐配裝、逐精調設定的證據閘門；未知即 null。
- `src/details.mjs`：有意義的「未精調／精調後／兩者比較」畫面。現有裸槍數值照常顯示，裝備後詳細倍率沒有證據便顯示「待驗證」，不把裸槍 1× 偷當成配裝後結果。

## 精調分類（依 2026 一般性攻略；不是 AKM 個別物件已驗證）

| 部位 | 一般性精調維度 | 研究到的取捨方向 |
|---|---|---|
| 槍管 | 配重、長度 | 開火穩定／瞄準移速；初速／開鏡速度 |
| 前握把 | 配重、厚度 | 額外後座／開鏡速度；移動據槍／瞄準移速 |
| 後握把 | 配重、厚度 | 額外後座／呼吸穩定；移動據槍／開鏡速度 |
| 槍托 | 配重、安裝位置 | 額外後座／呼吸穩定；開火時武器穩定／開鏡速度 |
| 托腮／托墊 | 視品項，可有安裝位置 | 必須先驗證能否裝在 AKM 上 |
| 瞄具 | 視品項，倍率與瞳距 | 光學畫面呈現，不能當槍口物理後座係數 |

## 何時能顯示「精調後 = xx×」？

應先有完整一筆紀錄：

- weaponId=akm；platform=mobile；gameMode=operations；具體 gameVersion，而非僅日期。
- **整套配裝** objectIds 與紀錄完全一致，不以槽位相同取代。
- 精調後額外包含一個**實際存在**的 tuningProfileId 與 tuningSettings，不能用名義上的「滿精調」替代。
- 同一設定的精確詳細倍率與配件精調前後畫面，能追溯證據：官方遊戲記錄／遊戲內截圖、來源 reference、checkedAt。
- 值的 metric ID 必須出現在白名單中，不能把開火時鏡頭穩定當作開火時武器穩定，不能把總控點數當作額外水平／垂直後座倍率。
- 不同遊戲版本、遊戲模式、PC/手機都不混用。

`src/precision.mjs` 支援這種對照，但**目前 production protocol 的 currentVersion 為 not-verified、沒有任何 profile 或實測紀錄，因此不會輸出一筆虛假的結果**。精調模式開關目前僅切換比較視圖，不會修改原本 4 大面板數字。

## 仍待進一步實機取樣

優先 AKM 上確實可裝的槍托：記錄未精調與精調後詳細屬性，包含全自動垂直／水平後座倍率、開火武器穩定、開火鏡頭穩定、開鏡時間和腰射散布。再逐槍口／前後握把擴展；不同配件的精調資格及相容父槽也須獨立核實。

## 驗收

Node 測試會驗證詳細欄位覆蓋、同配裝／平台／模式／版本／來源門檻以及嚴格拒絕無證據的值。Chromium 驗收會在裝槍托後切換三個精調檢視、檢查「待驗證」而非裸槍假值、確保切換不影響左側算術、並檢查網址分享狀態。

**備註**：網頁介面的研究數值仍是暫定估算；獨立的精調細節資料管線是為了未來有實測後可安全加入，而不是代表今日已能數值化精調效果。
